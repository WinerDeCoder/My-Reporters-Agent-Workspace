# My-Reporters-Agent-Workspace

A platform to manage, control and view agents that report on news and repos.

The first project here is **Tech Radar**: a local web app that collects rising GitHub repos and AI news, scores them, writes short cards with an OpenAI model, and shows a daily brief you can rate with 👍/👎.

## Stack

| Layer | Choice |
| --- | --- |
| Backend | Python 3.12+, FastAPI, APScheduler (in-process jobs) |
| Database | PostgreSQL 17 (pgvector image) in Docker, SQLAlchemy 2.0 async + asyncpg, Alembic |
| Collectors | httpx, tenacity, selectolax |
| LLM | OpenAI (Responses API, structured output) via the official `openai` SDK; settings in `config.yaml` -> `llm` |
| Frontend | React 19, Vite, TypeScript, Tailwind CSS, TanStack Query, React Router |
| Tooling | uv, ruff, pytest |

## Prerequisites

- [uv](https://docs.astral.sh/uv/) (installs Python for you)
- [Node.js](https://nodejs.org/) 20.19+ or 22 LTS
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (for Postgres)

## First-time setup

```powershell
# 1. Secrets
Copy-Item .env.example .env      # then fill in GITHUB_TOKEN and OPENAI_API_KEY

# 2. Database
docker compose up -d db

# 3. Backend
cd backend
uv sync                          # or: pip install -r requirements.txt
uv run alembic upgrade head
cd ..

# 4. Frontend
cd frontend
npm install
cd ..
```

## Running

**Development** (two terminals, hot reload):

```powershell
cd backend;  uv run fastapi dev app/main.py      # http://localhost:8000/docs
cd frontend; npm run dev                          # http://localhost:5173
```

The Vite dev server proxies `/api` to the backend.

**Daily use** (one process, one URL):

```powershell
cd frontend; npm run build; cd ..
cd backend;  uv run fastapi run app/main.py      # http://localhost:8000
```

When `frontend/dist` exists, FastAPI serves it alongside the API.

## Common tasks

```powershell
# Backend (from backend/)
uv run pytest                                    # tests
uv run ruff check . ; uv run ruff format .       # lint + format
uv run python -m app.cli collect trending        # run the Trending collector once
uv run python -m app.cli collect github          # snapshot tracked repos once (needs GITHUB_TOKEN)
uv run python -m app.cli momentum --top 20       # top repos by stars/day
uv run alembic revision --autogenerate -m "..."  # new migration after editing models.py
uv add <package>                                 # add a dependency, then refresh requirements.txt:
uv export --no-hashes --no-dev -o requirements.txt

# Frontend (from frontend/)
npm run typecheck
npm run gen:api      # regenerate TS types from the backend's OpenAPI (backend must be running)
```

## Configuration

- **`.env`**: `DATABASE_URL`, `GITHUB_TOKEN`, `OPENAI_API_KEY` and the Postgres credentials used by Docker Compose.
- **`config.yaml`**: interest keywords, brief time and timezone, top-N counts, collector intervals, and the `llm` section: OpenAI model, reasoning effort, max output tokens, timeout, optional `base_url`, card prompt file and monthly budget cap.

## Workflow and progress tracking

Work is spec-driven: each feature gets `specs/NNN-name/spec.md` (what), `plan.md` (how) and `tasks.md` (checklist) before code is written. Progress lives in those files and is rolled up into [STATUS.md](STATUS.md) by `python scripts/status.py`. Releases follow SemVer and are recorded in [CHANGELOG.md](CHANGELOG.md) and git tags. Full rules, including the Definition of Done: [CLAUDE.md](CLAUDE.md).

With Claude Code opened **in this folder**, these slash commands drive the workflow:

| Command | Does |
| --- | --- |
| `/status` | Refresh STATUS.md and summarize where things stand |
| `/spec <feature>` | Draft a new spec for review |
| `/plan <NNN>` | Approve the spec, write plan.md and tasks.md |
| `/tasks <NNN>` | Write or refresh the task checklist |
| `/qa <NNN>` | Run the spec's tests and record results in its test-case file |
| `/change <what>` | Record a requirement/spec/decision change with version bumps |
| `/done <NNN>` | Definition of Done: verify, update statuses, CHANGELOG, commit |
| `/release [X.Y.Z]` | Move Unreleased to a version, bump versions, tag |

A Stop hook (`scripts/check_tracking.py`) stops Claude from ending a turn when app code changed but no tracking file did, or when STATUS.md is stale.

```powershell
python scripts/status.py           # regenerate STATUS.md
python scripts/check_tracking.py   # run the tracking check by hand
```
